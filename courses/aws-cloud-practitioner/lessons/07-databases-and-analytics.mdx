      ## Relational vs NoSQL, and the shared responsibility model

      Storing data on EBS, EFS, Instance Store, or S3 is file-level. A
      **database** structures the data so you can build indexes, query
      efficiently, and define relationships between datasets.

      - **Relational databases (SQL)**: like Excel spreadsheets with links
        between tables. Use the SQL language for queries. Examples of
        engines: Postgres, MySQL, MariaDB, Oracle, SQL Server.
      - **NoSQL databases (non-relational)**: purpose-built for a specific
        data model with a **flexible schema** — data often stored as JSON with
        nested fields that can change over time. Benefits: easy to evolve,
        scale *out* (horizontal), high performance for their model. Types:
        key-value, document, graph, in-memory, search.

      **Managed databases on AWS** (RDS, DynamoDB, …) give you quick
      provisioning, high availability, easy vertical and horizontal scaling,
      automated backup and restore, upgrades, OS patching by AWS, and
      integrated monitoring. If you run your own database on EC2, *you* handle
      resiliency, backup, patching, high availability, fault tolerance, and
      scaling.

      :::tip **Exam tip:**
      "SQL / OLTP relational database" → RDS/Aurora. "Flexible schema, JSON,
      scale out" → NoSQL (DynamoDB, DocumentDB). With managed databases, AWS
      patches the OS — you never SSH into the instance.
      :::

      ## RDS: managed relational databases

      **Amazon RDS (Relational Database Service)** is a managed SQL database
      service supporting Postgres, MySQL, MariaDB, Oracle, Microsoft SQL
      Server, and Aurora. Advantages over running a DB on EC2:

      - Automated provisioning and OS patching (no SSH access — AWS manages
        the whole instance)
      - Continuous backups with **Point-in-Time Restore**
      - Monitoring dashboards, maintenance windows, vertical & horizontal
        scaling
      - Storage backed by EBS

      **RDS deployment options** (heavily tested):

      | Option | Purpose | Key facts |
      |--------|---------|-----------|
      | Read Replicas | Scale read workloads | Up to 15 replicas; writes go only to the main DB; improves read performance |
      | Multi-AZ | High availability / failover | Passive failover DB in another AZ; failover if the main DB or AZ fails; only 1 failover AZ |
      | Multi-Region | Disaster recovery + local reads | Read replicas across regions; lower latency for global reads; replication cost between regions |

      :::tip **Exam tip:**
      Read replicas = scale *reads* (writes stay on the main DB). Multi-AZ =
      *failover/high availability* (passive standby, one other AZ). If the
      question says "survive an AZ outage," the answer is Multi-AZ, not read
      replicas.
      :::

      ## Aurora: AWS's cloud-native relational database

      **Amazon Aurora** is AWS's proprietary (not open source) database,
      compatible with **PostgreSQL and MySQL**. It is cloud-optimized:

      - **5×** performance over MySQL on RDS, **3×** over Postgres on RDS
      - Storage grows automatically in 10 GB increments
      - More expensive than RDS (~20% more) but more efficient — and **not
        included in the free tier** (RDS is)
      - **Aurora Serverless**: automated database instantiation and
        auto-scaling based on actual usage; pay per second; great for
        infrequent, intermittent, or unpredictable workloads

      Aurora is the "RDS way" of running MySQL/Postgres in the cloud: you get
      the same managed benefits with better performance. Think of DocumentDB
      later as "Aurora for MongoDB."

      :::tip **Exam tip:**
      "Cloud-native MySQL/Postgres with 5× performance" → Aurora. "Unpredictable
      workload, no capacity planning, pay per second" → Aurora Serverless.
      Aurora is NOT in the free tier; RDS is.
      :::

      ## DynamoDB, DAX, and ElastiCache

      **Amazon DynamoDB** — fully managed **NoSQL key-value** database:

      - Replicated across **3 AZs**, distributed and **serverless** (no
        servers to provision)
      - Scales to millions of requests per second, trillions of rows, hundreds
        of TB of storage
      - **Single-digit millisecond latency**
      - Integrated with IAM for security; low cost with auto-scaling
      - Data model: a primary key (partition key, optionally + sort key) plus
        attributes; one table, no joins — data lives in a single table

      **DAX (DynamoDB Accelerator)** — a fully managed **in-memory cache for
      DynamoDB only**: 10× performance improvement, taking reads from
      single-digit milliseconds down to **microseconds**.

      **Amazon ElastiCache** — managed **Redis or Memcached** in-memory
      databases. High performance, low latency; reduces load off databases for
      **read-intensive workloads** by caching frequent queries.

      :::tip **Exam tip:**
      "Serverless key-value, single-digit ms" → DynamoDB. "Cache for
      DynamoDB" → DAX (it only works with DynamoDB). "Managed Redis or
      Memcached" → ElastiCache.
      :::

      ## Analytics: Redshift, EMR, Athena, QuickSight

      | Service | What it is | Key facts |
      |---------|------------|-----------|
      | **Amazon Redshift** | OLAP data warehouse | Based on Postgres but for analytics, not OLTP; **columnar storage**, Massively Parallel Query Execution (MPP); 10× better than other warehouses; petabytes of data; SQL interface; BI tools (QuickSight, Tableau); Redshift Serverless runs analytics without provisioning |
      | **Amazon EMR** | Hadoop clusters for big data | Creates Hadoop clusters of hundreds of EC2 instances; supports Spark, HBase, Presto, Flink; auto-scaling + Spot instances; use for data processing, ML, web indexing |
      | **Amazon Athena** | Serverless SQL on S3 | Query data directly in S3 with standard SQL — no loading; supports CSV, JSON, ORC, Avro, Parquet; **~$5 per TB scanned**; use compressed/columnar data to pay less; great for VPC Flow Logs, ELB Logs, CloudTrail |
      | **Amazon QuickSight** | BI dashboards | Serverless, ML-powered business intelligence; interactive dashboards, per-session pricing; integrates with RDS, Aurora, Athena, Redshift, S3 |

      :::tip **Exam tip:**
      "Analytics on data in S3 without loading it, using SQL" → Athena.
      "Data warehouse / OLAP / columnar" → Redshift. "Hadoop cluster" → EMR.
      "Dashboards / business intelligence" → QuickSight.
      :::

      ## Specialized databases and the selection table

      | Service | Type | Think of it as |
      |---------|------|----------------|
      | **DocumentDB** | NoSQL document (JSON) | "Aurora for MongoDB" — MongoDB-compatible, 3 AZ replication |
      | **Amazon Neptune** | Graph | Social networks, knowledge graphs (Wikipedia), fraud detection, recommendation engines |
      | **Amazon Timestream** | Time series | IoT/sensor data evolving over time; trillions of events/day |
      | **Amazon QLDB** | Ledger | Financial transactions journal; **immutable, cryptographically verifiable**; central authority (no decentralization) |
      | **Amazon Managed Blockchain** | Blockchain | Decentralized; join/create blockchain networks; Hyperledger Fabric & Ethereum |
      | **AWS Glue** | ETL | Managed extract-transform-load; fully serverless; Glue Data Catalog used by Athena/Redshift/EMR |
      | **DMS** | Migration | Database Migration Service; source stays available; homogeneous (Oracle→Oracle) or heterogeneous (SQL Server→Aurora) |

      **Quick selection guide:**

      - Relational / OLTP → **RDS or Aurora**
      - In-memory cache → **ElastiCache**; cache for DynamoDB → **DAX**
      - Key-value, serverless, low latency → **DynamoDB**
      - Data warehouse / OLAP → **Redshift**
      - Hadoop / big data → **EMR**
      - Query S3 with SQL, no servers → **Athena**
      - Dashboards / BI → **QuickSight**
      - MongoDB → **DocumentDB**; graph → **Neptune**; time series →
        **Timestream**; ledger → **QLDB**; blockchain → **Managed Blockchain**
      - Move/transform data → **DMS** / **Glue**

      :::tip **Exam tip:**
      "Financial transactions, immutable journal" → QLDB. "Decentralized,
      multiple parties, no central authority" → Managed Blockchain. "MongoDB"
      → DocumentDB. "Graph of relationships" → Neptune. "Time series" →
      Timestream. "ETL" → Glue. "Migrate a database" → DMS.
      :::
