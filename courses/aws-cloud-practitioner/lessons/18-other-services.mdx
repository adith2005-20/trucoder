      ## The "other services" section — one definition at a time

      AWS has *over 200 services*, and this section covers the ones that
      appear **sometimes, but rarely**, on the Cloud Practitioner exam. The
      good news: each of them comes down to **one definition and one use
      case**. If you remember the definition, you're set — there is no deep
      configuration knowledge to memorize. These questions are almost always
      high-level "pick-a-service" scenarios, so your job is to match a
      *keyword* in the question to the right service name.

      The most exam-tested pairing in this section is the difference between
      **Amazon WorkSpaces** and **Amazon AppStream 2.0** — both deliver
      Windows-like environments, but in very different ways.

      **Amazon WorkSpaces** is a managed **Desktop as a Service (DaaS)**
      solution to easily provision **Windows or Linux desktops** in the
      cloud:

      - Eliminates the need to manage **on-premises VDI (Virtual Desktop
        Infrastructure)** — users get a full virtual desktop instead
      - Fast and quickly scalable to **thousands of users**
      - Secured data — **integrates with KMS** for encryption
      - **Pay-as-you-go** with monthly or hourly rates; you pay for the
        desktops you actually use
      - Users connect with a **remote desktop client** and can launch *many*
        applications inside the desktop

      **Amazon AppStream 2.0** is a **desktop application streaming**
      service — it streams a *specific application* (e.g., Blender, Eclipse,
      OpenOffice) to any computer **from within a web browser**:

      - No virtual desktop to connect to — the app itself runs in AWS and is
        rendered in your browser
      - Works on **any device that has a web browser** (more compatibility
        than WorkSpaces)
      - You can configure an **instance type per application** (CPU, RAM,
        GPU — e.g., more GPU for a 3D modeling app)

      | | Amazon WorkSpaces | Amazon AppStream 2.0 |
      |---|---|---|
      | Delivers | A **full virtual desktop** (VDI) | **One application**, streamed |
      | Access | Remote desktop client | **Web browser**, any device |
      | Model | On-demand or always-on | Per application (CPU/RAM/GPU per app) |
      | Exam keyword | "Virtual desktops / VDI / DaaS" | "Stream an app in a browser" |

      :::tip **Exam tip:**
      "Give users a full Windows/Linux desktop in the cloud" → **WorkSpaces**.
      "Stream a single application (like Photoshop) into a web browser with
      no VDI" → **AppStream 2.0**. Also remember: to **minimize latency for
      WorkSpaces**, deploy them in regions **close to your users** — e.g.,
      one in the US for California staff and one in Europe for Paris staff.
      "Deploy close to users" is the general latency answer on the exam.
      :::

      ## AWS IoT Core & AWS Step Functions

      **AWS IoT Core** connects **IoT devices** to the AWS Cloud. *IoT*
      stands for "Internet of Things" — the network of internet-connected
      devices (a connected car, a smart light, a connected fridge) that
      collect and transfer data:

      - **Serverless, secure, and scalable to billions of devices and
        trillions of messages**
      - Acts as a **publish/subscribe (pub-sub)** hub so devices can
        exchange messages and communicate
      - Your applications can communicate with your devices **even when the
        devices aren't connected** (messages are queued)
      - Integrates with other AWS services — Lambda, S3, SageMaker — to
        gather, process, analyze, and act on device data

      **AWS Step Functions** builds a **serverless visual workflow** to
      orchestrate (coordinate) your **Lambda functions** — and much more:

      - You design a **state machine / graph**: at each step, what happens
        next on success or failure
      - Built-in features: **sequencing, parallel functions, conditions,
        timeouts, error handling**
      - Integrates with EC2, ECS tasks, on-premises servers, API Gateway,
        SQS queues, and many other AWS services
      - Supports a **human approval step** — e.g., a workflow pauses until a
        person clicks "Approve" or "Reject"
      - Use cases: **order fulfillment**, data processing, web applications,
        any workflow complex enough to need a visual graph

      :::tip **Exam tip:**
      Keyword → service: **"orchestrate / workflow / state machine / chain
      Lambda functions"** → **Step Functions**. **"connected devices /
      pub-sub for IoT / billions of devices"** → **AWS IoT Core**. A
      workflow that needs a *human approval step* is a classic Step
      Functions scenario.
      :::

      ## Email & marketing: Amazon SES vs Amazon Pinpoint

      **Amazon SES (Simple Email Service)** is a scalable **email sending**
      service — send transactional and marketing emails at scale. If the
      exam says "send email," SES is the service.

      **Amazon Pinpoint** is a scalable **two-way (inbound and outbound)
      marketing communications service**:

      - Sends **email, SMS, push notifications, voice, and in-app messages**
      - **Segment and personalize** messages with the right content for
        groups of customers; you can also receive replies
      - Scales to **billions of messages per day**
      - Use cases: run **campaigns** (bulk marketing email) and send
        **transactional SMS messages**
      - Message events (TEXT_SUCCESS, TEXT_DELIVERED, replies...) stream to
        **Amazon SNS, Kinesis Data Firehose, and CloudWatch Logs** for
        automation

      The key contrast with SNS/SES:

      | | SNS / SES | Amazon Pinpoint |
      |---|---|---|
      | Audience, content, delivery schedule | **Your application** manages each message | Managed by **Pinpoint** |
      | Campaigns | Not built-in | Message **templates**, delivery schedules, **highly-targeted segments**, full campaigns |
      | Role | Notification / email plumbing | **Next evolution** of SNS/SES for full marketing |

      :::tip **Exam tip:**
      **SES = email sending.** **Pinpoint = marketing campaigns with
      segmentation and personalization** (SMS-heavy, billions of messages).
      If the question mentions "create segments, message templates, and
      delivery schedules for a marketing campaign," the answer is Pinpoint —
      not SNS or SES, where your own application would have to manage all of
      that.
      :::

      ## Media, meetings, satellites & AR/VR

      This group of services is easy to confuse, so keep the one-liners
      straight:

      | Service | One-liner | Typical use case |
      |---------|-----------|------------------|
      | **Elastic Transcoder** | Converts **media files stored in S3** into formats required by consumer **playback devices** | S3 input bucket → transcoding pipeline → S3 output bucket (phone/tablet/PC formats) |
      | **MediaConvert** | File-based **video transcoding** (VOD — video on demand) | Prepare video files for delivery in multiple formats |
      | **MediaLive** | **Live video** processing/encoding for broadcast | Stream live events to viewers |
      | **Amazon Chime** | Secure **video meetings, calls, and chat** | Online meetings and communications |
      | **Amazon Connect** | **Cloud contact center** (contact center as a service) | Set up a customer service center in the cloud; pairs with Amazon Lex for conversational bots |
      | **Ground Station** | Fully managed **satellite communications** | Download satellite data to your VPC within seconds |
      | **Amazon Sumerian** *(discontinued Feb 2023)* | Create and run **VR, AR, and 3D applications** | 3D models with animations; ready-to-use templates, no programming or 3D expertise needed |

      A few exam-relevant details worth remembering:

      - **Elastic Transcoder** is **easy to use, highly scalable, cost
        effective (duration-based pricing — you pay only for the time your
        media was transcoded), fully managed, and secure**. You never
        provision EC2 instances to convert files.
      - **AWS Ground Station** provides a **global network of satellite
        ground stations near AWS regions**; satellite data can be sent to
        **S3 or an EC2 instance** inside your VPC. Use cases: weather
        forecasting, surface imaging, communications, video broadcasts.
      - **Sumerian** apps are accessible **via web-browser URLs** or on
        popular AR/VR hardware, with **no programming or 3D expertise
        required** (ready-to-use templates and assets).

      :::tip **Exam tip:**
      "Convert a video from S3 into phone/tablet formats" → **Elastic
      Transcoder** (older name) or **MediaConvert** (current VOD service).
      "Satellites / download data from space" → **Ground Station**.
      "AR/VR / 3D applications without code" → **Sumerian**. "Live
      broadcast stream" → **MediaLive**.
      :::

      ## Building & testing apps: Amplify, AppSync & Device Farm

      **AWS Amplify** is a set of tools and services to **develop and deploy
      scalable full-stack web and mobile applications** — think of it as the
      **Elastic Beanstalk for web and mobile apps**:

      - One suite for **authentication, storage, API (REST and GraphQL),
        CI/CD, PubSub, analytics, AI/ML predictions, and monitoring**
      - Source code can come from **AWS, GitHub, or other providers**
      - Amplify Studio wires up an **Amplify backend** that leverages
        existing services under the hood: **S3, Cognito, AppSync, API
        Gateway, SageMaker, Lex, Lambda, DynamoDB**

      **AWS AppSync** builds a backend for mobile and web apps that stores
      and synchronizes data **in real time** using **GraphQL**:

      - Client code for your APIs can be **generated automatically**
      - Integrates with **DynamoDB and Lambda**
      - **Real-time subscriptions** and **offline data synchronization**
      - Amplify can leverage AppSync in the background for GraphQL backends

      **AWS Device Farm** is a fully managed service that **tests your web
      and mobile applications against real desktop browsers, real mobile
      devices, and tablets**:

      - Tests run **concurrently on multiple devices** to speed up execution
      - You can configure device settings — **GPS, language, Wi-Fi,
        Bluetooth**, and more
      - Uses **real devices, not emulators**; you can interact with the
        devices and receive **reports, logs, and screenshots** to catch bugs
        early across many screen sizes

      :::tip **Exam tip:**
      "GraphQL in the question" → **AppSync** (a very strong hint).
      "One place to build/deploy a full-stack web or mobile app (auth,
      storage, API, CI/CD)" → **Amplify**. "Test my app on many *real*
      phones/tablets before release" → **Device Farm** (real devices, not
      emulators).
      :::
